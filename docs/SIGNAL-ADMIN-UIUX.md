# Admin UI 기준

## 목표

Admin은 수집 서버 운영자가 Job 상태, 데이터 품질, 사용자/알림/설정을 빠르게 확인하고 조치하는 도구다. 화면은 라이트/다크 모두에서 명확해야 하며, 설정 항목은 기능 단위로 한 줄씩 충분한 폭을 가진다.

## 정보 구조

| 메뉴 | 내용 |
|---|---|
| 대시보드 | 수집 상태, 주요 실패, 최신 데이터 |
| 콘텐츠 수집 | Job 설정, 실행, 이력, 오류 로그 |
| 콘텐츠 데이터 | 뉴스, 유튜브, 캘린더, 인사이트 |
| 앱 사용자 | 사용자, 디바이스, 약관 동의, 알림 이력 |
| 알림/푸시 | 공지 작성, 발송 대상, 발송 이력 |
| 설정 | Provider, RSS, YouTube 채널, **종목 프로필**, 약관, 앱 설정 |

## UI 원칙

- 목록은 한 row에 하나의 항목을 보여준다.
- 실패/주의 상태는 기본 카드 스타일을 유지하고 왼쪽 강조선과 상태 배지로 표시한다.
- 버튼 스타일은 primary, secondary, danger, ghost 네 가지로 제한한다.
- 설정 화면은 카드 중첩을 피하고, 섹션 제목 + 설명 + 입력 row 구조를 사용한다.
- 다크 테마에서 흰색 카드가 튀어나오지 않도록 CSS 변수만 사용한다.

## Job 화면

- Job row: 이름, 타입, 주기, enabled, 최근 실행, 최근 결과, lock 상태, 주요 액션.
- 상세: 설정, 수동 실행, 실행 이력, 로그, lock 해제.
- lock TTL은 Job별 설정 가능해야 한다.

## 사용자 화면

- 상단: 검색/필터.
- 중앙: 사용자 row 목록.
- 하단/상세: 선택 사용자 정보, 약관 동의, 디바이스, 소셜 연결, 알림, 인증 세션 이력.
