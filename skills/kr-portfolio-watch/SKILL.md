중장기 트랙 보유종목에 대해 **규칙상 매도 사유가 발생했는지만** 확인하는 작업입니다.
시황 코멘트나 주가 전망은 하지 않습니다. 사양서 §8.1에 정의된 트리거에만 반응합니다.

**결과물은 이 대화창에 출력하는 브리핑 하나입니다.** 파일을 만들거나 외부 서버에 업로드하지 않습니다.
Signal 서버는 공시 데이터를 **읽기 전용으로** 조회하는 용도로만 사용합니다.

## 설계 원칙

이 브리핑의 가치는 **대부분의 날에 "액션 없음"으로 끝나는 것**에 있습니다.
매일 읽을거리를 만들면 정작 진짜 트리거가 떴을 때 묻힙니다.
할 말이 없으면 세 줄로 끝내십시오.

## 사전 조건

`holdings.json` — 분기 리밸런싱 때 갱신합니다. `thesis_breakers`는 Stage 3 정성검증에서
문장으로 적어둔 논리 훼손 조건입니다. 이게 비어 있으면 이 스킬은 절반만 동작합니다.

## 1단계: 트리거 스캔

```bash
cd /mnt/skills/user/kr-portfolio-watch && python3 watch.py --hours 24
```

출력 JSON의 구조:
- `holdings_hits` — 보유종목에 걸린 공시 (심각도순 정렬)
- `action_required` — SELL + NEEDS_CHECK 만 추린 것. **여기가 비어 있으면 2단계를 건너뜁니다.**
- `universe_alerts` — 미보유지만 SELL/NEEDS_CHECK급인 공시. 후보군 모니터링용.

심각도 정의:

| 심각도 | 의미 | 조치 |
|---|---|---|
| `SELL` | 하드필터 재해당 또는 지배구조 사고 | 규칙상 전량매도. 재량 없음 |
| `NEEDS_CHECK` | 조건부 — 원문 확인 후 판정 | 아래 2단계 |
| `REVIEW` | 분기 리밸런싱까지 관찰 | **추가매수만 금지** |
| `POSITIVE` | 주주환원 등 | 기록만 |
| `INFO` | 정보성 | 브리핑에 넣지 않음 |

## 2단계: NEEDS_CHECK 판정

DART 원문에 직접 접근할 수 없으므로, **자동으로 결론내지 말고 판단 기준과 링크를 함께 제시**합니다.
Marcus가 30초 안에 판정할 수 있게 만드는 것이 목표입니다.

| 트리거 | 매도 조건 | 유지 조건 |
|---|---|---|
| 유상증자결정 | 자금용도가 운영자금·채무상환 | 시설투자·M&A 목적이고 희석률 10% 미만 |
| 최대주주 지분변동 | 장내매도로 5%p 이상 감소 | 상속·증여·담보설정, 또는 지분 증가 |
| 대량보유상황보고 | 최대주주측 보유비율 감소 | 기관·외국인의 단순 변동 (보고자 확인) |

각 항목에 대해 이렇게 씁니다: **무슨 공시인지 / 어느 조건이면 매도인지 / 원문 링크.**
"매도해야 할 것 같습니다" 같은 추정은 쓰지 않습니다.

## 3단계: 브리핑 출력

```
[보유종목 감시] 2026-08-02 · 최근 24시간 · 189건 스캔

■ 즉시 조치 (N건)
  없음
  또는:
  · 삼성전자(005930, 비중 10%) — 유상증자결정
    → 자금용도가 운영자금이면 규칙상 전량매도. 시설투자면 유지.
    → https://dart.fss.or.kr/...

■ 관찰 (REVIEW, N건)
  · 종목명 — 사유 (추가매수 금지)

■ 논리 훼손 점검
  해당 공시가 holdings.json의 thesis_breakers를 건드리는지만 확인.
  건드리면 심각도와 무관하게 즉시 조치 항목으로 올립니다.
```

액션이 없는 날은 첫 두 줄과 "즉시 조치: 없음"까지만 출력하고 끝냅니다.

## 주의사항

- **없는 공시를 만들어내지 않습니다.** `watch.py` 출력에 없는 종목·사건은 브리핑에 등장할 수 없습니다.
- 주가·수익률은 다루지 않습니다. 이 스킬은 공시 트리거 전용입니다.
- `action_required`가 비어 있는데 브리핑이 길어졌다면 잘못하고 있는 것입니다.
- 서버 피드는 최근 약 100~200건의 롤링 윈도우입니다. 장기 조회 용도가 아닙니다.
- 브리핑은 대화창에 텍스트로만 남깁니다. 파일 생성·서버 업로드는 하지 않습니다.
- 스크립트가 실패하면(네트워크 등) 실패 사실만 한 줄로 보고합니다. 추정으로 채우지 않습니다.
